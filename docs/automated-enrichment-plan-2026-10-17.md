2. ЧТО ИСПРАВИЛА 2.8.1
Главные проблемы старого enrichment:
- Facebook показывает фоновые и активные слои одновременно.
- Одинаковый post ID встречается во множестве anchors.
- Нельзя определять пост только по одной ссылке.
- Facebook виртуализирует длинные ветки комментариев: старые DOM nodes исчезают при скролле.

2.8.1:
- выбирает активный открытый пост структурно;
- сохраняет guard-проверки идентичности;
- работает только с нужным постом;
- накапливает комментарии между scroll/snapshot циклами, поэтому виртуализация их не теряет;
- не перезаписывает архив меньшим числом комментариев;
- умеет включать «Все комментарии»;
- восстанавливает дату из шапки поста, если обычный parser ее не взял;
- при подозрении/смене поста останавливается до записи.

5. ПОЧЕМУ НУЖНА АВТОМАТИЗАЦИЯ
Bookmarklet исчезает после перехода на следующий URL. Поэтому вручную открывать 236 постов нельзя.

Предлагаемая форма:
маленькое Chrome extension или userscript, который живет на facebook.com и переживает навигацию.

Предпочтительный UX:
Владимир один раз открывает Facebook и нажимает «Обогатить архив».
Дальше инструмент сам:
1) берет следующий ID из очереди;
2) открывает /groups/pumpkinlatte/posts/<ID>/;
3) ждет стабильной загрузки;
4) запускает core 2.8.1;
5) пишет результат в Supabase;
6) фиксирует status;
7) переходит к следующему;
8) делает паузы и имеет Stop/Resume.

6. ОЧЕРЕДЬ И СТАТУСЫ
Нужна явная очередь. Минимальные статусы:
- pending
- processing
- enriched
- partial
- unavailable
- failed
- skipped_guard

Полезные поля:
- facebook_post_id
- batch_key
- old_comment_count
- expected_comment_count
- new_comment_count
- attempts
- last_error
- started_at
- finished_at
- collector_version

Не обязательно сразу создавать новую таблицу, если безопаснее сначала сделать очередь в клиенте из RPC/select. Но для полноценного resume/audit лучше отдельная archive.enrichment_queue или аналогичная структура после проектирования.

7. SAFETY / GUARDS — ОБЯЗАТЕЛЬНО СОХРАНИТЬ
Перед записью:
- URL post ID должен совпадать с очередью;
- выбранный active post должен пройти structural guard;
- text fingerprint должен совпадать до/после enrichment;
- автор не должен внезапно смениться;
- нельзя сохранять меньше уже имеющихся комментариев;
- если DOM/route меняется — abort без записи;
- недоступный пост только помечается, существующая запись не удаляется;
- никаких массовых destructive update.
