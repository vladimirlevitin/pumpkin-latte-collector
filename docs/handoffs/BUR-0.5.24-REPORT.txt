2. ЦЕЛЬ И СОГЛАСОВАННЫЙ ОБЪЁМ
Выгружать доступные пользователю посты/комментарии группы с информацией для базы данных, сохранять прогресс и продолжать исторический сбор. Верхняя начальная граница хранится отдельно от нижней границы уже выгруженной истории. Периодическое пополнение идёт от начала ленты до прежней верхней границы, после подтверждённого сохранения обновляет верхнюю, не трогая нижнюю. Пока только новые посты с их комментариями; старые обсуждения при update не досматриваются. Медиа — исходные ссылки и метаданные, не файлы.

3. ИСТОЧНИКИ И ПРОИСХОЖДЕНИЕ
Изучены правильный longrun-extension в fix/longrun-feed-collector-v0.1.1 и история обеих репозиториев collector/archive. Нужный код отдельных authors/persistAuthor и author_key найден и сопоставлен с Буром. Отвергнутые HTML-сборщики Татьяны не использовались как эталон.

Все 2792 числовых ключа авторов соответствуют author:SHA256(ID). Битых author/post references нет; parent_comment_key в этом старом экспорте не заполнен. Его метка core 2.8.5-longrun-safe совпадает с c0db6ad/47873c3, линия manifest 0.1.2. Не доказано, что его создал 0.1.1 или один конкретный коммит. Часть старых дат выведена алгоритмом, их нельзя считать точным временем Facebook.
Изучены исходники 0.5.22 и реальный пользовательский ZIP 0.5.23 (SHA-256 8d682507175a515bc123086b378d0a3488efbda678e2ddc3850960fa1b7db19d).
Два raw JSON: 0.5.22 — 50 постов/441 комментарий; 0.5.23 — 20/98. Повторный аудит новой логикой PASS: сохранены все 70/539 и исходные тексты; граф авторов без битых ссылок. В обоих исходных JSON точных post timestamps нет: они не выдуманы.
Два ранее сохранённых HTML Facebook проверены без выполнения сохранённых скриптов и без сетевого доступа: 30 постов/43 комментария, 29 авторов постов/30 меток даты; точных времён в разметке нет. Это реальная сохранённая разметка, не новый живой сбор.
Подробности: LEGACY-COMPARISON.md, DEVELOPMENT-STATE.md.

4. МАТРИЦА ТРЕБОВАНИЙ И РЕГРЕССИЙ
Область | Реализация/проверка | Предел доказательства
Группы | Состояние отдельно по group/mode, без специального fallback для backpackIL; worker/incremental fixtures PASS | Не прогонялись все варианты групп Facebook
Автор поста | Собственный header; numeric/profile/vanity/groups-user; anonymous явно; comment author не попадает в post; DOM/graph tests PASS | Удалённого/скрытого автора восстановить нельзя
Отдельные авторы | authors + author_key; numeric SHA совместим; имя без ID привязано к владельцу, одноимённые люди не склеиваются; SQL E2E PASS | Name-only остаётся слабой идентичностью
Даты | Только явное точное время в published_at; исходная подпись/source/precision отдельно; post/comment не смешиваются; fixtures PASS | Нет основания превращать относительную подпись в точное время
Текст | Короткие, link-only/media-only; длинные тексты без прежних 30k/12k и 20-variant обрезаний; fixtures PASS | Только текст, реально раскрытый и доступный в DOM
Ссылки | Текст/адреса постов и комментариев, включая ссылки без обычного body; repeat merge/SQL metadata PASS | Отсутствующие в старом raw ссылки не восстановлены
Медиа | Принадлежность post/comment; исключены avatar/emoji/UI; image/video metadata, blob временный не выдаётся за постоянный URL; tests PASS | Файлы не скачиваются; внешние URL могут истечь
Комментарии | Сохраняется каждый срез до прокрутки; 70 виртуализированных срезов через несколько Deep passes PASS | Это сценарий модели виртуализации, не длительный живой Facebook
Длинные ответы | Owned dialog, 25 раскрытий, отсутствие старого лимита 10, safe pause/detach/stall; fixtures PASS | Новые layouts Facebook могут потребовать адаптации
All comments | Собственное меню и наблюдаемый результат; неподтверждённая смена incomplete; fixtures PASS | Отсутствие селектора даёт not_exposed/unknown, не доказанную полноту
Порядок ленты | Проверка New posts, composite heading/owned dialog; привязка доказательства к document; повтор после reload/смены; tests PASS | Ранжирование/модерация/вставки задним числом не дают математической гарантии полного обхода
Checkpoint | Точный ID, без сравнения величины ID; проверенные seek/rewind, защита pinned/чужих постов; popup + reload + restart PASS | Скорость восстановления на большой живой группе не измерена
Историческая граница | Тот же живой feed document продолжает пакеты; потеря document вызывает recovery; tests PASS | Исчезнувший недоступный checkpoint требует проверки, не обходится догадкой
Две границы | head/tail отдельно; незавершённый update не двигает head; commit/recovery/pinned tests PASS | Live reorder сценарии ограничены
Пополнение | 5 постов -> 1 новый -> повтор без новых, tail неизменен; confirmed old posts не идут в Deep/export; installed ZIP PASS | Новые комментарии старых постов намеренно не обновляются
Сохранность | Реальный download complete + SHA до атомарного commit job/history/checkpoint/receipt; storage failure replay/restart PASS | Это локальное подтверждение файла, не квитанция импорта в базу

Поставка | Один ZIP после регрессий, manifest в корне; установка именно распакованного ZIP и оба сквозных сценария PASS | Живой Facebook проверяет пользователь

5. ПРОВЕДЁННЫЕ ПРОВЕРКИ
Полный набор новой версии: 42/42 файла PASS локально Windows. Логи release-0524-regression.log.
Архивный pipeline: все шесть Node suites PASS (receipt, index, search, API, pgvector E2E, author graph E2E). На Windows для уменьшения пика памяти Node использован heap 512 MiB и один поток WASM compilation; SQL/утверждения тестов не ослаблены. Лог release-0524-pipeline.log.
Python: 9 importer tests, 6 watcher tests PASS; portal browser test PASS. Отдельный graph E2E запускает настоящий Python watcher против локального HTTP Storage/RPC и настоящего SQL, включая серверный commit с потерянным подтверждением.
После упаковки: release-0524-zip-incremental.log и release-0524-zip-checkpoint.log — PASS. Временный тестовый профиль и загрузки изолированы от пользовательского Chrome/Downloads/watcher. Вторая загрузка профиля сохранила ID расширения и checkpoint.
Ранее память на Windows мешала запуску PostgreSQL/WASM. Ошибки нехватки памяти не засчитывались как успешные тесты. Текущий отчёт опирается на завершённые прогоны, а не на предположение об их результате.
GitHub Actions для опубликованного исходного состояния: см. проверки PR #4/ветки. Исторические прогоны и исправленная гонка тестового popup описаны в DEVELOPMENT-STATE.md; старые красные прогоны не скрыты.

6. ЧТО НЕ ПРОВЕРЕНО И НЕ РАЗВЁРНУТО
Авторизованный сбор на живом Facebook этой новой сборкой; многочасовой обход большой группы; полная статистическая сверка всех доступных постов/веток произвольной группы; реальная скорость seek; скрытые/удалённые/недоступные записи; все текущие языки/layouts Facebook. Пользователь прямо принял живую проверку на себя. Статусы unknown/incomplete не заменены утверждением полной выгрузки.
Production Supabase/WordPress и установленный watcher не менялись. Новые staging SQL/RPC и index bridge только локально протестированы; в установочный ZIP они не входят. Расширение не требует ключа Supabase и не делает импорт автоматически. Развёртывание БД — отдельное последующее действие.

7. ОБНОВЛЕНИЕ
Распаковать ZIP, заменить файлы в прежней папке Бура, нажать «Обновить» на chrome://extensions; не удалять расширение/папку. Затем перезагрузить вкладки Facebook. Ключи chrome.storage и имя/версия IndexedDB сохранены. Новый content guard/version ping позволяет загрузить новый код после обновления; данные не сбрасываются.

Для основного чата: исходный код, полный набор тестов, итоговая матрица, архив и этот отчёт находятся в PR #4; отчёт также сохранён в Google Drive / OpenAI / Эстафета между чатами. Следующий практический шаг — пользовательский живой прогон 0.5.24 и анализ полученного raw JSON/диагностики. Нельзя объявлять универсальную полноту Facebook доказанной по этим fixtures и нельзя менять production как продолжение этой поставки без отдельного запроса.
