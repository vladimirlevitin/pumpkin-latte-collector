## Выводы по исходникам
1. Старая линия извлекала собственный текст через `[data-ad-preview="message"]`, `[data-ad-comet-preview="message"]`, затем `[dir="auto"], div[lang], span[lang]`, отделяя кнопки и вложенные комментарии. В новом `core.js` уже есть аналогичный fallback в `extractCard`; слепое копирование не устранит неисправность.
2. Старое распознавание привязывало публикацию к permalink-ссылке из верхней части `[role="article"]` (`permalinkMeta`). Новый Бур также требует подтверждённого permalink ID и намеренно не придумывает ID, но при отсутствии собственной DOM-карточки делает `url_identity_existing_discovery`.
3. Критический регресс **не в количестве тестов**, а в маршрутизации результата: `content.js` посылал fallback через `deepSnapshot`; `background.js/completeDeep` увеличивал `deepDone` без проверки fallback. В результате `exportComplete` мог подтвердить checkpoint неполного пакета.
4. Исправление в ветке `fix/bur-0524-deep-receipt-guard`: fallback и обрезанный текст переводятся в failed/retry без ложного `deepDone`; перед commit экспорт проверяет все строки пакета.
5. Неподтверждённый вопрос: **почему** четыре конкретные карточки Facebook не распознаны. JSON содержит диагностический симптом, но не исходную DOM-структуру. Для исправления селектора потребуется воспроизводимый снимок DOM проблемной карточки. Не менять селекторы по догадке.
6. Политика следующего теста: короткий живой пакет; проверить Deep каждого поста, полноту текста/комментариев, отсутствие ложного checkpoint. Не считать fixtures доказательством полноты Facebook.
