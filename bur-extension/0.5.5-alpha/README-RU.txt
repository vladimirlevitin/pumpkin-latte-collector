FB БУР 0.5.4-alpha — ИСПРАВЛЕНИЕ ЭКСПОРТА
25 октября 2026 г.

Причина: export.html открыт в отдельной вкладке, поэтому MessageSender
содержит tab. Проверка привязки сборщика возвращала для exportSlice
{ok:true,result:{ignored:true}}, а export.js разворачивал отсутствующий items.
Теперь собственная страница export.html получает {ok:true,result:{job,items,total}}.
Исключение действует только для exportSlice и точного URL страницы расширения.
Проверка чужих Facebook-вкладок сохранена. Неожиданный ответ теперь показывает
понятную ошибку, не выдаёт пустой архив за успешный результат.
collector_version берётся из manifest.

КАК ВЫГРУЗИТЬ УЖЕ СОБРАННЫЕ ДАННЫЕ
1. Обновите существующее расширение НА МЕСТЕ: распакуйте ZIP в прежнюю
   папку расширения с заменой файлов, затем нажмите «Обновить» на его карточке
   в chrome://extensions. Не удаляйте расширение и не загружайте копию из
   другой папки: нужно сохранить прежний ID и его хранилище.
2. Откройте панель Бура и нажмите существующую кнопку «Экспорт».
   Откроется export.html, JSON скачается автоматически. Facebook открывать
   и запускать новый сбор не требуется. «Скачать ещё раз» повторяет скачивание.
3. Не нажимайте «Начать»: новый сбор по прежним правилам очищает архив группы.

DB bur-collector-v05, версия БД 1 и ключ burCollectorJob-v05 не изменены.
Экспорт читает посты IndexedDB группы сохранённого задания из storage.local.
Если данные или запись задания удалены, восстановление этой версией невозможно.
Сборщик, кнопки панели и автоматический переход к экспорту сохранены;
в content.js изменена только строка версии для согласования с background.
Живой Facebook в проверках 0.5.4 не использовался.

ЧТО ИСПРАВЛЕНО ПО ЖИВОМУ ЭКСПОРТУ 0.5.1
1. Окно «Посмотреть N ответов», открытое самим Буром, больше не считается посторонним препятствием: ответы извлекаются, окно закрывается, deep продолжается.
2. Для ответа используется reply_comment_id, а parent_id связывает его с родительским комментарием.
3. Авторы по Facebook-ссылкам /groups/.../user/<id> сохраняются отдельно в author/author_url.
4. Добавлен fallback для permalink-страниц, где основной пост не обёрнут в role=article.
5. В deep раскрывается по одному контролу за цикл, чтобы Facebook успевал стабилизировать UI.

Запуск без ручной помощи должен дойти до done; отдельно проверить, что посты с «Посмотреть N ответов» больше не падают, а в JSON появляются author и parent_id у вложенных ответов.

FB БУР 0.5.1-alpha — УСТОЙЧИВЫЙ КОЛЛЕКТОР FACEBOOK
25 октября 2026

НАЗНАЧЕНИЕ
Chrome MV3-расширение этапа 1: собрать максимум доступных публикаций
Facebook-группы и доступные комментарии/ответы в сырой JSON.
Никакого ранжирования, Gemini, эмбеддингов, Supabase или отбора «полезного».


ИСПРАВЛЕНИЕ 0.5.2
Живой тест 0.5.0 дошёл до 17-го поста, после чего Facebook сам перевёл
служебную вкладку на главную facebook.com. Старый onUpdated только будил
content script, но не возвращал URL; content script на главной странице
не мог продолжить deep.

0.5.2 исправляет именно этот сценарий:
- при завершившемся переходе вкладки background сверяет URL с ожидаемым
  post_id текущего deep-элемента;
- если Facebook увёл вкладку, Бур сам возвращает её на permalink;
- максимум 3 автоматических возврата подряд на один post_id;
- если Facebook уводит тот же пост 4-й раз, ошибкой помечается только этот
  пост и очередь автоматически идёт дальше;
- ручная пауза/Продолжить для такого случая не требуется;
- в панели подписи уточнены: «Успешно» и «Сейчас», чтобы не было двух
  разных строк «Подробно».

ГЛАВНОЕ ИЗМЕНЕНИЕ 0.5.0
Версии 0.4.x были архитектурно слишком зависимы от человека: обычный popup,
неактивная вкладка или неожиданный URL могли поставить весь deep-проход на
паузу. Для многочасового универсального сборщика это неверно.

В 0.5.0 политика другая:
- ошибка/удаление/таймаут/постороннее окно одного deep-поста = failed только
  для этого поста, затем автоматически следующий;
- неактивная вкладка сама по себе не ставит очередь на паузу;
- если Facebook увёл служебную вкладку на другой URL, deep-проход сам
  возвращает её к ожидаемому permalink;
- загрузка страницы будит collector через tabs.onUpdated; popup расширения
  не обязан оставаться открытым;
- вложенные dialog-обёртки одного permalink-поста считаются одним целевым
  представлением, а не посторонним окном;
- при препятствии в разведке сборщик до 5 раз автоматически возвращается
  к канонической ленте группы;
- при молчании ленты watchdog до 3 раз автоматически перезагружает ленту.

ГЛОБАЛЬНАЯ ПАУЗА остаётся только для действительно неустранимых случаев:
закрыта служебная вкладка либо Facebook многократно не даёт получить ленту
(например, проверка входа/доступа). Обычный плохой пост не должен требовать
участия пользователя.

УСТАНОВКА ДЛЯ ПОЛЕВОГО ТЕСТА
1. Распакуйте ZIP в НОВУЮ отдельную папку.
2. В chrome://extensions отключите прежний FB Бур.
3. «Загрузить распакованное расширение» -> новая папка с manifest.json.
4. Откройте обычную ленту нужной группы: /groups/<group>/ .
5. В панели убедитесь: FB Бур v0.5.2-alpha.
6. Для первого живого приёма поставить 20 и нажать «Начать / продолжить»
   ОДИН РАЗ. Дальше не помогать программе вручную.

ВАЖНО
0.5.0 использует новую локальную БД bur-collector-v05 и новый job key.
Старые 0.4.x тестовые 32/53 поста намеренно НЕ переносятся: они не имеют
ценности по сравнению с проверкой чистого полного цикла.

ЧТО СЧИТАЕТСЯ УСПЕХОМ
Один запуск на живой группе дошёл до stage=done без ручного спасения.
deep_done + deep_errors = deep_total. Ошибки отдельных публикаций допустимы;
остановка всей очереди на обычном посте — дефект. После этого отдельно
проверяется качество 3 реальных веток комментариев.

ОГРАНИЧЕНИЯ
Facebook DOM меняется, часть материалов может быть недоступна, а полнота
всех комментариев не гарантируется. Расширение работает только с тем DOM,
который доступен авторизованному пользователю, без обхода ограничений.
