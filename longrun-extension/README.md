# Pumpkin Latte — длинный сбор из ленты (v0.1.1, кандидат на пилот)

**Цель:** собирать **новые** посты, комментарии и ссылки на медиа из тех элементов группы, которые браузер Facebook уже показал пользователю. Источник — активная вкладка https://www.facebook.com/groups/pumpkinlatte/ с обычным доступом пользователя.

Это **не** старая 50-постовая очередь обогащения. Для удаления/недоступности исходных постов эта версия просто продолжает проход по тем записям, которые показывает лента. Специальный повторный обход уже известных постов будет отдельной задачей.

## Исправления v0.1.1

- Исправлен счётчик ошибок синхронизации, который мог ломать интерфейс при старте.
- IndexedDB теперь использует одно переиспользуемое соединение, чтобы долгие прогоны не создавали сотни открытых соединений.
- Ошибка отправки не блокирует очередь навсегда: есть защитное завершение и отложенная повторная попытка.
- Панель статуса не исчезает через две секунды; при запуске она появляется на вкладке.
- Повторный запуск рассчитывает количество **дополнительных** новых постов, не останавливаясь сразу из-за старого счётчика.
- Неидентифицированные проблемные карточки различаются по текстовому отпечатку, а не по их порядковому номеру в DOM.

**До теста в Facebook это всё ещё кандидат на пилот, а не подтверждённая многочасовая работа.**

## Что изменено

1. Ошибка разбора одного поста не останавливает проход. После трёх ошибок одну и ту же проблемную карточку пропускаем до перезапуска.
2. Ошибка фото/видео/вложения не уничтожает текст поста — данные медиа необязательны.
3. Если Facebook временно перестаёт показывать новые элементы, проверяем повторно с задержками до 30 секунд. После **15 минут без роста ленты и новых постов** автоматически приостанавливаем, чтобы не зависнуть навсегда.
4. Новые записи и контрольные точки хранятся в локальной IndexedDB. При повторном запуске данные не очищаются.
5. Подтверждённая синхронизация в Supabase идёт прямо через `collector-ingest` с publishable key, **без всплывающего окна**. Есть ограниченные повторы и очередь для повторной отправки неподтверждённых записей.
6. Chrome-расширение сохраняет настройку запуска и отслеживает вкладку раз в минуту. При возвращении на страницу группы оно может возобновить сбор с сохранённой локальной базой, но позиция прокрутки Facebook может не сохраниться.
7. Новые посты, старые и неотправленные повторы безопасно различаются по постоянным ключам в архиве; результат синхронизации ещё нужно подтвердить реальным пробным запуском.

## Установка (Windows / Chrome)

- Скачать [готовый ZIP](https://raw.githubusercontent.com/vladimirlevitin/pumpkin-latte-collector/fix/longrun-v0.1.1-package-qa/downloads/pumpkin-latte-longrun-v0.1.1.zip).
- Распаковать в отдельную постоянную папку (не удалять после установки).
- В Chrome открыть `chrome://extensions`, включить «Режим разработчика», нажать «Загрузить распакованное расширение», выбрать папку с файлом `manifest.json`.
- **На время теста выключить предыдущее расширение «Pumpkin Latte Enrichment Pilot»**, иначе два скрипта будут конфликтовать.
- Открыть ленту `https://www.facebook.com/groups/pumpkinlatte/` и нажать иконку нового расширения.
- Для первого теста указать **20** новых постов и нажать «Начать / продолжить». После этого проверить число сохранённых записей в Supabase. Только затем увеличивать до 500–1000 и далее.

## Важные границы

- Браузер должен оставаться открытым, компьютер не должен переходить в сон; активная вкладка Facebook предпочтительнее фоновой. Facebook может ограничивать доступ или останавливать прокрутку; программа это не обходит.
- Пауза после 15 минут отсутствия прогресса — нормальное безопасное завершение, а не потеря данных.
- Если расширение установлено, **не менять его папку**, иначе Chrome может потерять к нему доступ.
- На первом запуске не ставить сразу 5000 или 50000: это верхний предел целевого числа записей, а не подтверждённая производительность.
- Нельзя утверждать, что в Supabase попали все 120000 участников или все многолетние посты: программа видит только то, что реально загружает Facebook в ленте.
- Даже если медиа не загрузилось, ссылки на медиа могут сохраниться, но сами файлы не копируются — отдельно нужна задача скачивания медиа по доступным URL с обработкой недоступности.
- Ни схема Supabase, ни Edge Functions, ни WordPress/production при подготовке этой ветки не менялись.
- **До проверки на реальной ленте это release candidate, а не проверенный часовой сбор.**

## Восстановление

При ошибке или паузе откройте новую вкладку ленты, вызовите расширение и нажмите «Начать / продолжить». Данные IndexedDB не стирайте. Если в статусе «waiting_for_group_tab», просто откройте ленту. Если в статусе «paused_by_collector», можно начать заново после проверки Facebook.

## Проверки

- GitHub Actions: `node --check` для четырёх скриптов, проверки манифеста и контракта, ZIP сборка.
- Критические сценарии для теста глазами: обычный проход 20 постов, недоступная картинка в видимом посте, прерывание загрузки ленты, временная потеря сети, повторное открытие браузерной вкладки, дедупликация после перезапуска, подсчёт строк в Supabase.

## Дальше

После подтверждённых 20 записей оценить процент ошибок и размер очереди, затем запустить 100–200 и 1–2 часа. **Автоматическую очередь досбора** из 185 постов с `needs_enrichment=true` нужно модернизировать отдельно: её текущий серверный endpoint выдаёт только 50 записей и не хранит статус «недоступен». Не смешиваем эти две задачи.
